## 统一资源监控

资源监控沿用当前远程终端的 SSH 连接，面向 Linux 主机，默认显示在右侧栏。原系统监控与 GPU/NPU 入口整合为三个页面：

- **概览**：保留系统、CPU、内存、网络和磁盘指标
- **硬件**：按探测结果展示 GPU、NPU、RGA、编解码器、温度和 PSI 资源压力等卡片
- **进程**：查看系统进程或 GPU/NPU 计算进程

硬件卡片统一采用标题、设备信息、实时指标和可展开详情。GPU 优先显示型号，节点路径移入详情；RGA 使用硬件类型与核心编号，详情解释调度器编号的含义。温度按芯片温区、CPU、GPU/NPU 等分组，突出最高温度及对应传感器。长路径与原始输出可以换行、选择和复制

卡片按设备实际能力显示，NX、Ascend 或普通 Linux 主机不会因无权访问 debugfs 就出现无依据的 Rockchip RGA/NPU 卡片。页面、sudo 开关与设备折叠偏好按主机保存

### Rockchip

| 模块 | 展示内容 |
| --- | --- |
| RGA | 按驱动调度器展示各单元负载，标明 RGA2/RGA3 类型、核心编号与硬件组成 |
| RKNN NPU | 各核心负载、频率和驱动版本；设备整体负载放入详情，不计入核心数量 |
| GPU / DDR | 按 devfreq 设备展示频率与可获取的负载；GPU 型号优先使用驱动提供的信息 |
| MPP / VPU | 编解码会话数量、PID、格式、分辨率、实际编码 FPS 及其合计，核心时钟、解码任务索引与增长率 |
| 温度 / 资源压力 | thermal 传感器温度，以及内核提供的 CPU、内存和 I/O PSI 指标 |

MPP 详情补充配置帧率、码率控制、码率、GOP、Profile、驱动报告的内存、总线时钟、使能计数、驱动版本与诊断信息。各来源分别记录状态和最后成功采样时间

MPP 的实际编码 FPS 来自驱动 `fps_calc`，与配置帧率分开显示。解码任务增长率不是解码 FPS，核心时钟和使能计数也不是硬件利用率；只有驱动提供有效负载接口时才显示相应负载

### NVIDIA Jetson Orin NX

检测到 Jetson 后，使用有界的 `tegrastats` 采样补充 GPU 利用率与温度，并合并 devfreq 频率，避免仅有频率、无法判断活动状态。板载 GPU 只显示一张卡片，共享系统 RAM 不作为独立显存展示

Orin NX 的媒体引擎包括 NVENC、NVDEC、两个 NVJPG 单元、VIC 和 OFA，分别对应视频编码、视频解码、JPEG 编解码、图像合成与转换、光流加速。根据接口可用情况展示：

- runtime PM 运行或休眠状态、频率和调频策略
- ACTMON 硬件活动负载，需要相应节点的读取权限
- 两次电源计数之间的唤醒占比，累计唤醒与休眠时间放在详情

引擎休眠时不沿用 ACTMON 的旧负载；唤醒占比与编解码利用率分开标注，频率不用于推算负载。公开节点已在实机核验，授权后 ACTMON 的真实业务负载仍需进一步核验

### Huawei Ascend 310B

兼容板载设备的 `Bus-Id = NA` 和 NPU/芯片双编号。在原有 AI Core 利用率、内存、温度、功耗和健康状态基础上，按实际设备编号追加查询：

- AI CPU 与控制 CPU 利用率
- 内存带宽利用率与内存频率

另通过 `/proc/umap` 的 VDEC、VENC、VPC、H.264/H.265 编码及码率控制节点采集 DVPP 信息，按视频解码、视频编码与图像处理分组，展示已创建通道、格式、尺寸、PID、驱动帧率和可用的编码码率。配置帧率、缓冲区、任务计数、耗时和诊断内容放在详情

已创建通道数不代表正在处理任务的通道数，驱动帧率与任务耗时也不直接转换为硬件利用率。六个节点的空闲输出已在实机核验；有业务通道的解析由模拟样本覆盖，仍需在实际编解码负载下核验字段口径

## 采集授权与状态

默认以 SSH 登录用户读取。需要提权的指标可通过「采集设置 → 配置免密读取…」授权：在应用内输入远端 sudo 密码，配置成功后自动开启 sudo 采集并重新检测硬件，密码不保存

授权范围限定为 Rockchip RGA/NPU、MPP 时钟树及 Jetson ACTMON 的十二个固定节点，只允许有长度上限的读取；配置过程校验专用 sudoers 文件，失败时回滚。日常采集不挂载 debugfs、不修改调频策略，也不启用驱动追踪。此操作需要当前 SSH 用户已有 sudo 管理权限；关闭采集开关不会删除远端规则

采集保留以下区别，便于判断数据是否可用：

- **未提供、权限不足、读取失败、超时**分别展示，缺失数据不填成 `0`
- **历史读数**标明状态，避免把上次成功的结果当作本轮数据
- **独立采集域**隔离硬件失败，CPU、内存等系统采样继续运行
- **超时暂停**在硬件读取超时后停止该域的新请求，重连后再尝试；收起面板后不发起新请求

指标取决于板卡、BSP、驱动、内核接口和权限。配置授权只能解决读取权限问题，不能补出驱动未提供的数据。现阶段不推算缺失的硬件利用率，也未提供监控历史导出或监控 Agent/MCP 接口

## SFTP 与终端文件侧栏

**macOS 拖出下载**：SFTP 独立标签页和终端文件侧栏都支持把远程文件或目录拖到 Finder 文件夹或桌面，多选后可一起拖出。落点就是下载目标，传输进度仍由原面板展示；完整下载后才向系统报告完成。Windows 和 Linux 继续使用应用内的下载入口

**侧栏排序**：终端文件侧栏增加修改时间与类型列，配合名称和大小排序。点击列标题切换排序方向或恢复名称顺序，目录始终在前；刷新或切换目录后保留排序，列宽可调整

上游已有的双栏传输、拖入上传和断点续传继续保留，上述内容主要扩展系统拖出下载与终端侧栏体验

## 书签别名与终端目录联动

在 SFTP 或文件侧栏的「打开目录/书签」中，可以给书签设置可选别名，例如把 `/srv/services/payment/logs` 命名为「支付服务日志」。已有书签可修改或清空别名；路径仍是书签身份与跳转目标，别名可以重复。本地与远程书签分别保存，远程书签别名随已有同步机制同步，旧书签可继续使用

长别名在末尾省略，长路径在中间省略，保留路径两端；悬停查看完整内容。显示省略不改变保存内容、搜索范围或实际路径

在远程终端中使用书签：

1. 按 `⌘⇧J`，其他平台按 `Ctrl+Shift+J`，或在终端右键菜单选择「目录书签…」
2. 按完整别名或路径搜索，使用方向键选择，回车或单击将转义后的 `cd` 命令填入该终端
3. 检查命令后，在终端按回车执行；已启用的目录跟随会根据 shell 报告更新文件侧栏

文件侧栏工具栏、目录右键菜单和书签对话框也提供「在终端进入」。操作固定到来源终端与连接，关闭或重连后需要重新选择；独立 SFTP 标签的书签可通过同一主机的终端书签搜索使用

当前终端联动面向 POSIX shell 的 SSH 终端，不支持 Windows 远程 shell。填入命令会替换当前输入行，不自动执行；vim 等全屏程序接管终端时拒绝输入。快捷键可在设置中修改

## 构建与维护

本 Fork 当前仅提供源码构建，原作者安装包与自动更新渠道不包含这些定制。构建步骤见 [README](../README.zh-CN.md#从源码构建)，具体操作见[使用手册](manual.zh.md)

维护使用一个定制 `main`、独立功能分支和临时上游同步分支，通过 Merge 保留上游历史。工作流定期检查上游更新并创建同步 PR，主分支要求检查通过后合并；采集样本统一放在 `tests/fixtures/`，供解析器与 UI 测试复用。详见 [Fork 维护指南](fork-maintenance.zh.md)
